# Verification: `console-server`

Prefix `V-CS-N`. Parent criteria cited by their `V-N`.

Each line ends with the run that covers it, recorded 2026-09-15 against the tree
`vite-console` (PR #8) left, or with the fact that none does. `vite-console`
verified its own `V-VC-N`; four criteria here were never picked up by that pass.

- V-CS-1 `build` — `pnpm turbo run build` succeeds with no `RAILWAY_*` variable set; **Amended by `vite-console`:** there is no framework to ask for a runtime. The equivalent guarantee is that `vite build` succeeds with no `RAILWAY_*` variable set — the build never imports the server — and that `start` runs one long-lived process. *Covered:* `pnpm build` runs `vite build` with no `RAILWAY_*` set, in `pnpm verify`; `apps/console/package.json` `start` is one long-lived `tsx src/server/main.ts`.
- V-CS-2 `unit` — `toConsoleError` maps a `ConfigError` raised by a missing `RAILWAY_TOKEN_KIND` to `500` with the body `{ error: 'console-misconfigured' }`; the body carries no variable name and no other prose, the variable is named in the server log, and no Railway request is made (fake `fetch` records zero calls). *(Reworded 2026-09-15 by `D-OPS-6`. It previously asserted that the first `GET /api/container/state` answers this, which `V-55` makes impossible — the process exits before it listens — and it claimed a `message` in the body that `consoleErrorSchema` has no field for.)* **No run.** `toConsoleError` maps `ConfigError` to `plain('console-misconfigured', 500)` at `apps/console/src/server/errors.ts:53-57`, but there is no test file for `errors.ts`; `config.test.ts` covers `configFromEnv` throwing, which is a different assertion. `T-CS-1` is open on this.
- V-CS-3 `unit` — Two `EventSource` clients and a third that reconnects each receive the current state as their first event; the fake `fetch` records the same number of reads as with zero clients (`V-26`, `V-26a`). *Covered:* `apps/console/src/server/sse.test.ts`, "opens with the current state and the current operation, costing no read" and "a reconnecting browser is told the press is still running"; `packages/container-core/src/poller.test.ts`, "the read count does not depend on how many clients are listening".
- V-CS-4 `unit` — A `: ping` comment is written at least once per 20 s of fake time on an open stream; closing the response unsubscribes (listener count returns to its previous value). *Covered:* `sse.test.ts`, "pings inside 20 s so a proxy keeps the socket — V-CS-4" and "a disconnect unsubscribes, and stops costing anything".
- V-CS-5 `unit` — Driving Start → starting → up → second press → Stop → down → `GET /state` against the fake Railway produces exactly the sequence of `ContainerState` phases the experiment recorded, and the second press is a `409` with no fake-Railway call (`V-17`, `V-18`). **No run for the sequence.** The second-press half is covered — `apps/console/src/server/routes.test.ts`, "two simultaneous presses issue one mutation; the other gets 409", with the fake Railway recording one mutation. The first half, driving Start → starting → up → Stop → down against `test/fake-railway.ts` and asserting the phases the experiment recorded, is not tested. `T-CS-4` is open on this.
- V-CS-6 `unit` — Each scripted failure — not-authorized, `429` with `Retry-After: 30`, `429` without, the `numReplicas` validation body, a thrown `fetch` — yields the status and `ConsoleError` of parent §9, and the state served by `GET /state` afterwards is the last known one (`V-13`, `V-14`, `V-25`). *Covered:* `routes.test.ts`, "the error contract — Q-UI-7" — the parametrised failure → status/code table, "mirrors Retry-After when Railway sent one, and omits it when it did not", and "never forwards Railway prose, only the trace id". *Not covered:* the trailing clause, that `GET /state` afterwards serves the last known state.
- V-CS-7 `unit` — With `CONSOLE_PASSPHRASE=x`: `POST /up` without the cookie → `401`; `POST /api/session` with the wrong passphrase → `401`; with the right one → `204` + `Set-Cookie` (HttpOnly, SameSite=Strict); then `POST /up` → not `401`. Without the variable, `POST /up` needs no cookie (`V-20`). *Covered:* `routes.test.ts`, "the passphrase gate — V-20, V-CS-7" — all four cases, plus the cross-origin refusal.
- V-CS-8 `unit` — Every `ConsoleError` body the routes can produce parses with `consoleErrorSchema` from `@repo/contracts` (snapshot over all kinds, `V-13`). **No run.** `consoleErrorSchema` is never imported by a server test; `routes.test.ts` asserts status and `error` code but does not parse the body against the schema, and there is no snapshot over all kinds. (`sse.test.ts` does parse, but against `containerStateSchema` and `operationEventSchema`.) `T-CS-3` is open on this.
- V-CS-9 `live` — `V-16`: a headless browser loading the running console makes requests to its own origin only. **No run.** `live`; no headless-browser test exists. `routes.test.ts` "refuses a cross-origin press" is the server-side half, not the browser-side claim. `T-CS-5` is open on this.
