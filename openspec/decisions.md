# Decisions

> **Schema:** `| ID | Status | Statement |`
>
> **Prefix by capability:** `D-API-N`, `D-UI-N`, `D-SEC-N`, `D-OPS-N`.
>
> **Statuses.** `ratified` — signed off. `proposed` — follows from research but not
> yet signed. `superseded` — replaced by a successor. `planned` — a number
> reserved for a decision that has not been argued yet, so that a task may refer
> to it before it exists.
>
> **Mutation rule.** A ratified decision is not edited. It is superseded by a new
> `D-<CAP>-N` that references it. An agent does not move `proposed` to `ratified`.
>
> Every decision records the alternatives that were rejected. A decision without
> them is a note, not a decision. A `planned` row is the single exception: it
> reserves a number and states what for, and has no argument yet — which is what
> `planned` means.

## Tokens and secrets — `D-SEC-N`

| ID | Status | Statement |
|---|---|---|
| D-SEC-1 | proposed | The Railway API token is never exposed to the browser. Calls to `backboard.railway.com` are made from a server the console owns, and the client talks only to that server.<br><br>**Rejected:** calling the GraphQL endpoint directly from the browser with the token in an environment variable. | D-SEC-2 | proposed | **The deployed demo sets `CONSOLE_PASSPHRASE`: the two mutating routes require a session cookie, the two reading routes stay open.** This expands the `planned` row that `T-1.4` was waiting for, and overturns the default recorded there — *no gate* — on the grounds that a public URL with two buttons that spend the owner's money and change real infrastructure should not be pressable by whoever finds it. The mechanism is already built and is not what this decides: `apps/console/src/server/session.ts` signs an HMAC over the cookie's own expiry (8 h, `HttpOnly; SameSite=Strict; Secure`, constant-time comparison), `POST /api/session` exchanges the passphrase for it, and `routes.ts` asserts it on `POST /api/container/up` and `/down` only. The README says that the demo is gated and where the passphrase comes from, and nothing more.<br><br>**Recorded consequence, so that it is written down rather than discovered:** the HMAC key is random per process, so restarting the console signs every open session out. For a demo that is acceptable; for anything with more than one reviewer it is the first thing to change.<br><br>**Rejected:** an unauthenticated demo, which is what the `planned` row's default said. It is defensible only while the URL is unguessable, and an unguessable URL is not an access control — it is a secret that every reviewer, every forwarded message and every browser history now holds. The gate was already written, so the saving was one environment variable. **Rejected:** asking the reviewer to supply their own Railway token instead. The state of one demo container is not a secret, the first paint would need the cookie before it could show anything at all, and `D-UI-3` wants a reader to see the truth without being asked for anything. The ability to *change* the container is what is worth a gate. Resolves `Q-SEC-4`. |
